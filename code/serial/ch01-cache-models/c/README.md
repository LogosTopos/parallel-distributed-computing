## 顺着代码读

| 部分 | 观察什么 |
| --- | --- |
| `CacheLine`、`NoCoherence` | `valid` 区分无效副本与数值 0，`dirty` 记录写回责任 |
| `nc_read/write/clean/invalidate` | 命中旧缓存、从旧主存装入、写回与无效化的区别 |
| `wb_read/write/writeback/evict` | 未命中时由 owner 供数，写入时手动遍历其他有效副本 |
| `migration_and_io` | WT/WB 迁移、设备输入/输出的旧值，以及修复步骤 |
| `protocols` | 写无效与写更新、换写者、逐出所有者前写回 |
| `traffic` | 连续写与交替读写的广播和缺失计数 |
| `explore` | 独立记录最近写入值，枚举读、写、写回和逐出序列 |

`P1` 对应下标 0。`I` 表示无效，`*` 表示无一致性模型中的脏副本。协议模型用单独的 `owner` 表示谁负责写回；其他有效副本也可以含有最新值。`Mem=0(stale)` 表示主存不具备直接供数的资格，即使某次写入碰巧又把值改回 0，也仍须按 owner 处理。

## 关键预期

- WT 迁移：主存已经是 1，P1 命中 0；使 P1 失效后读到 1。
- WB 迁移：P1 留着新值，P2 从旧主存取得 0；仅写回 P1 仍不能修复 P2 已装入的旧副本。
- DMA 输入只改 `memory`，DMA 输出只读 `memory`；它们不是真实设备调用。
- 写无效后其他副本变为 I；写更新后其他有效副本都含新值。两者在显式写回前都允许主存落后。

事件统计应与原 Python 模型对应：

| 模式 | 策略 | 更新广播 | 无效广播 | 未命中 | 缓存供数 |
| --- | --- | ---: | ---: | ---: | ---: |
| burst | update | 3 | 0 | 0 | 0 |
| burst | invalidate | 0 | 1 | 2 | 2 |
| interleaved | update | 3 | 0 | 0 | 0 |
| interleaved | invalidate | 0 | 3 | 6 | 6 |

广播计数按一次写操作计，不按接收者计；不包含预热与最终写回。计数不是硬件耗时。

## 已执行的验证

2026-09-15，Apple Clang 17.0.0、arm64 macOS，C11，`-O2 -Wall -Wextra -Wpedantic -Werror` 编译通过。演示与 `--test` 实际通过，输出见 [results.txt](results.txt)。

自检覆盖错误读取与修复、拒绝丢弃脏数据、事件计数，并对两种策略各枚举所有长度不超过 5 的操作序列。每一步有 10 种操作，合计检查 222,220 次状态转移；写入值按层交替为 0/1。检查有效副本、返回值、所有者和无所有者时的主存。这是该有限串行模型的有界检查，未验证真实并发协议。
