# C：让多个工作线程分担任务

[教学路线](../../../notes/programming/ch01-teaching-guide.md) · [源代码](demo.c)

4 个 POSIX 工作线程处理 12 项任务。第 i 项计算 `i*i`，并用 `nanosleep` 模拟任务占用时间。前三项分别为 120、110、100 ms，其余各为 20 ms。

线程生命周期使用 pthread API；开始闸门、任务分配和结果归约都在代码里显式实现。每个线程有独立局部和，主线程在 `join` 后相加，因此没有多个线程无保护地修改一个总和。

## 两种调度

| 模式 | 手动实现方式 | 要观察的现象 |
| --- | --- | --- |
| `static` | `id * TASKS / WORKERS` 到 `(id+1) * TASKS / WORKERS` | worker 0 分到三个慢任务，其他线程可能先完成并等待 |
| `dynamic` | 互斥量保护 `next_task++`，一次领一个任务 | 空闲线程继续领任务；任务数量可以不均，但占用时间更均衡 |

串行延迟总和是 510 ms；静态分块的最长任务链是 330 ms；理想动态分配中，前三个线程各做一个慢任务，第四个线程及后来空闲的线程分担短任务。**这些是按设定推导的模型量，不是本机测量结果。** 实际时间包括调度、锁、打印与唤醒开销，不能承诺固定加速比。

`sleep` 会让出处理器，所以单核机器也可能显示等待任务的重叠。它演示并发和调度，不证明 CPU 密集计算在多核上的加速。

## 使用方法（本次未执行线程程序）

要求支持 pthread 的 macOS/Linux 环境和 C11 编译器。在仓库根目录：

```sh
make api-check       # 仅语法和编译期诊断
make parallel        # 可选：只构建两个线程示例
# 以下为使用方式，不属于本次已经执行的检查：
build/ch01/parallel-c static
build/ch01/parallel-c dynamic
```

日志记录任务的 `begin/end`、线程编号和相对毫秒数。观察某个任务尚未 `end` 时，其他线程是否已经 `begin`。每个任务编号应恰好出现一对 begin/end，最终总任务数应为 12，总和应为 650。程序核对这两个最终值；日志顺序和每个动态工作线程的任务数不固定。

## 四个可对照源码的教学点

1. **同步起点**：所有线程登记 ready；主线程设置 start 并广播。它是一次性闸门，不是可循环使用的屏障。
2. **共享状态保护**：领取任务时加锁，取出编号就解锁。把 sleep 放进这把锁内会妨碍并发领取。
3. **条件变量**：等待会暂时释放锁，醒来后重新获得锁；每次都用循环重新检查条件。
4. **同步终点**：主线程等待全部 `join`，再读取每个线程的结果槽，完成手动归约。
