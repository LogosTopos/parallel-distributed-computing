## 1. 先画出错在哪里

将教材中的 X、X' 分别记为 0、1。每次读取前先填“读取来源”和“返回值”，再对照 C 程序：

| 情形 | 最新值 | 错误读取的来源 | 模型中的修复 |
| --- | --- | --- | --- |
| WT，P2 写后迁移到 P1 | 主存和 P2 | P1 的旧缓存 | 使 P1 旧副本失效 |
| WB，P1 写后迁移到 P2 | P1 脏缓存 | 主存，之后也进入 P2 缓存 | 写回 P1，再使 P2 旧副本失效 |
| WT，设备向主存输入 | 主存 | CPU 旧缓存 | 设备完成后、CPU 使用前使旧副本失效 |
| WB，设备从主存输出 | CPU 脏缓存 | 主存 | 设备读取前完成写回 |

再切换写无效／写更新，观察**主存仍旧时，读取也可以正确**：协议负责找到最新副本。题图中的主存 I 应理解为旧主存副本不能作为当前权威数据源。

## 2. 把“同时工作”和“正确共享”分开观察

C 线程示例中，固定分块把前三个慢任务给同一个线程；动态领任务允许空闲线程继续工作。观察 begin/end 的重叠与最后等待的线程，再检查最终和 650。

接着沿代码回答：

1. `next_task++` 为什么必须在互斥区？如果两个线程都看到同一个旧编号会发生什么？
2. 为什么延迟应放在解锁之后？
3. 为什么每线程先算自己的局部和，而不是每项任务都抢一个全局总和？
4. 主线程为什么在 join 之后才读取结果？

这里的延迟只是把重叠和等待放大到容易观察的尺度，实际平方计算很短。**并发指执行进度可以交错，CPU 并行指多个核同一时刻执行计算**；sleep 演示不能替代多核性能实验。

## 3. 把一次缓存写展开成一串消息

C 的 `wb_write()` 在一个函数内完成全部失效。C++ 将这一步拆开：请求写入、通知其他副本失效、等待 ACK、交付写完成回复。这样就能看到通信时延和同步依赖。

同时检查三个相互独立的层次：

- **消息传输正确性**：环形队列不覆盖未读消息、不从空队列读取，条件变量负责等待。
- **协议正确性**：收到全部所需确认之后才允许写者完成；主存落后时向 owner 取数。
- **进度**：等自己回复时仍处理失效与供数请求；应用完成后仍服务其他节点，直到最终关闭。

本例只共享一个值，所以 home 必须为冲突操作确定顺序。多节点并发并不意味着对同一地址的任意操作都能无序完成。

## 4. 再认识现成 API

读完手动任务分配和消息协议后，再看 [OpenMP 用法与缓存维护的区别](openmp-usage.md)。`parallel for`、`schedule`、`reduction` 可以表达共享内存工作分配；它们不会把本例自动变成跨机器程序，也不替代设备 DMA 的缓冲区交接。
